# 自动发布新版本

这份文档是 Codex 发布新版本时的操作说明。真正执行 Git 操作的脚本是项目根目录的 `Publish-Next-Release.bat`，本文件负责记录使用方式和约束。

## 给大模型的提示词

以后需要发布新版本时，可以直接对 Codex 说：

> 请按照项目 `docs/发布新版本.md` 的规则发布下一个版本。先检查工作区和当前分支，确认应该推送的代码已经提交且工作区干净，然后执行项目根目录的 `Publish-Next-Release.bat`。执行完成后检查 GitHub Actions 和 Release 状态，并告诉我新版本号、Release 链接和是否发布成功。

如果工作区存在未提交或未跟踪文件，不能直接发布，应先停止并列出这些文件。

## Codex 的执行规则

1. 读取本文件和项目根目录的 `AGENTS.md`。
2. 执行 `git status --short` 和 `git branch --show-current`。
3. 只有在当前分支明确、工作区干净、用户已经提交了要发布的代码时，才执行脚本。
4. 通过 PowerShell 调用脚本时设置 `RELEASE_NONINTERACTIVE=1`，避免等待键盘输入：

   ```powershell
   $env:RELEASE_NONINTERACTIVE = '1'
   & '.\Publish-Next-Release.bat'
   if ($LASTEXITCODE -ne 0) { throw '版本发布脚本失败' }
   ```

5. 脚本成功后，等待并检查对应的 GitHub Actions；标签为 `vX.Y.Z`，Release 版本也应为 `vX.Y.Z`。
6. 如果项目中存在 `docs/releases/vX.Y.Z.md`，Action 会使用它作为 Release 描述；不存在时会使用 GitHub 自动生成的更新说明。
7. 不要在普通代码修改任务中自动执行本脚本。只有用户明确要求发布版本时才执行。

## 脚本做什么

脚本假定用户已经提交了要发布的代码，然后依次执行：

1. 检查 Git、仓库和工作区状态。
2. 读取 `CodexQuotaWidget.csproj` 的 `<Version>`。
3. 将版本号的最后一段加一，并按十进制进位。例如：
   - `0.0.1` → `0.0.2`
   - `0.0.9` → `0.1.0`
   - `0.9.9` → `1.0.0`
4. 更新项目版本号，并自动创建一个只包含版本号变更的提交。
5. 创建带注释的标签，例如 `v0.1.1`。
6. 推送版本提交和标签：

   ```text
   git push origin HEAD
   git push origin v0.1.1
   ```

7. 标签推送后触发 `.github/workflows/release.yml`，由 GitHub Actions 编译、测试、生成安装包和发布 Release。

脚本会拒绝处理未提交的修改，也会拒绝重复创建本地已有的标签。版本提交或标签创建失败时，不会自动回滚文件，便于保留现场排查。

## 手工运行

也可以直接双击项目根目录的：

```text
Publish-Next-Release.bat
```

双击运行会在结束时等待按键；Codex 通过命令行调用时使用上面的 `RELEASE_NONINTERACTIVE=1`，脚本会直接返回结果。

## Release 描述

若希望自定义 Release 页面中的更新说明，请在运行脚本前提交：

```text
docs/releases/v0.1.1.md
```

文件名中的版本号要和即将发布的标签一致。由于脚本要求运行前工作区干净，这个说明文件必须先提交，再运行发布脚本。

## 当前脚本内容

下面的代码与项目根目录的 `Publish-Next-Release.bat` 保持一致；实际执行时以该 `.bat` 文件为准。

```bat
@echo off
setlocal EnableExtensions DisableDelayedExpansion

cd /d "%~dp0"
title Codex Quota Widget - 发布下一个版本

echo.
echo ================================================
echo   Codex Quota Widget - 发布下一个版本
echo ================================================
echo.

where git >nul 2>&1
if errorlevel 1 (
    echo [错误] 未找到 Git，请先安装 Git 并重新打开此脚本。
    goto :failed
)

if not exist ".git\HEAD" (
    echo [错误] 当前目录不是 Git 仓库：%CD%
    goto :failed
)

set "DIRTY="
for /f "delims=" %%S in ('git status --porcelain') do set "DIRTY=1"
if defined DIRTY (
    echo [错误] 工作区存在未提交的修改（包括未跟踪文件），请先提交或处理：
    git status --short
    goto :failed
)

for /f "usebackq delims=" %%V in (`powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "$raw = [System.IO.File]::ReadAllText('CodexQuotaWidget.csproj'); $match = [regex]::Match($raw, '<Version>(\d+)\.(\d+)\.(\d+)</Version>'); if (-not $match.Success) { exit 2 }; $major = [int64]$match.Groups[1].Value; $minor = [int64]$match.Groups[2].Value; $patch = [int64]$match.Groups[3].Value + 1; if ($patch -ge 10) { $patch = 0; $minor++ }; if ($minor -ge 10) { $minor = 0; $major++ }; '{0}.{1}.{2}' -f $major, $minor, $patch"`) do set "NEXT_VERSION=%%V"

if not defined NEXT_VERSION (
    echo [错误] 无法读取 CodexQuotaWidget.csproj 中的三段式 Version。
    goto :failed
)

set "NEXT_TAG=v%NEXT_VERSION%"
echo 当前版本：读取成功
echo 下一个版本：%NEXT_VERSION%
echo 目标标签：%NEXT_TAG%
echo.

git rev-parse --verify -q "refs/tags/%NEXT_TAG%" >nul 2>&1
if not errorlevel 1 (
    echo [错误] 本地已经存在标签 %NEXT_TAG%，为避免重复发布，脚本已停止。
    goto :failed
)

echo [1/5] 更新项目版本号...
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "$path = 'CodexQuotaWidget.csproj'; $next = $env:NEXT_VERSION; $raw = [System.IO.File]::ReadAllText($path); $updated = [regex]::Replace($raw, '(<Version>)\d+\.\d+\.\d+(</Version>)', ('${1}' + $next + '${2}'), 1); if ($updated -eq $raw) { throw 'Version element was not updated.' }; [System.IO.File]::WriteAllText($path, $updated, [System.Text.UTF8Encoding]::new($false))"
if errorlevel 1 (
    echo [错误] 更新项目版本号失败。
    goto :failed
)

echo [2/5] 提交版本号变更...
git add -- CodexQuotaWidget.csproj
git commit -m "准备发布 %NEXT_TAG%"
if errorlevel 1 (
    echo [错误] 版本号提交失败，未创建标签。
    goto :failed
)

echo [3/5] 创建带注释的 Git 标签...
git tag -a "%NEXT_TAG%" -m "Release %NEXT_TAG%"
if errorlevel 1 (
    echo [错误] 创建标签失败。
    goto :failed
)

echo [4/5] 推送版本提交到 GitHub...
git push origin HEAD
if errorlevel 1 (
    echo [错误] 版本提交推送失败，暂未推送标签。
    goto :failed
)

echo [5/5] 推送标签到 GitHub，触发 Release Action...
git push origin "%NEXT_TAG%"
if errorlevel 1 (
    echo [错误] 标签推送失败。
    goto :failed
)

echo.
echo [完成] 已推送 %NEXT_TAG%。
echo       GitHub Actions 将自动编译、测试、打包并发布 Release。
echo.
if defined RELEASE_NONINTERACTIVE exit /b 0
pause
exit /b 0

:failed
echo.
echo 操作未完成，项目文件没有被自动回滚，请根据上面的提示处理。
if defined RELEASE_NONINTERACTIVE exit /b 1
pause
exit /b 1
```
